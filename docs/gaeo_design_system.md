# GAEO 디자인 시스템

작성 2026-08-15 · 적용 대상: `index.html` · `about.html` · `rotation.css` · `insight-rail.css` ·
`generate_snapshots.js`가 찍는 스냅샷 템플릿

## 왜 이 문서가 있나

기능을 추가할 때마다 새 색·새 배지·새 카드를 하나씩 얹다 보니, 화면이 조용한 금융 리포트가
아니라 **알록달록한 AI 대시보드**처럼 변해 갔다. 이 문서는 그 습관을 멈추기 위한 기준이다.

앞으로 Claude Code든 Codex든, 새 화면을 만들기 전에 이 문서를 먼저 읽는다.

## 목표 한 줄

> 정보가 많아도 **조용하고 정돈되어** 있으며, Apple식 여백·타이포그래피와
> 정제된 금융 리포트가 결합된 화면.

## 핵심 규칙 (요약)

이 여덟 줄만 지켜도 대부분 해결된다.

1. **No per-analyst colors** — 분석가별 고유색을 만들지 않는다
2. **No decorative gradients** — 장식용 그라데이션 금지
3. **No decorative emoji** — 섹션 제목마다 emoji를 붙이지 않는다
4. **No pill proliferation** — 모든 상태를 배지로 만들지 않는다
5. **Semantic market colors only** — 빨강·파랑은 시장 방향에만
6. **Typography and spacing first** — 계층은 색이 아니라 타이포·여백으로
7. **Apple-inspired editorial finance** — 화려함보다 읽히는 것
8. **Mobile-first readability** — 375px에서 먼저 읽히는지 본다

## 1. 색

### 기본 팔레트

| 역할 | 값 |
|---|---|
| 캔버스 | `--bg` (라이트 `#F5F5F7`) |
| 카드 | `--paper` (흰색) |
| 본문 | `--ink` / `--t2` / `--t3` / `--dim` |
| 구분선 | `--line` (neutral 1px) |
| 브랜드 액센트 | 애플 블루 계열 1개만, 제한적으로 |

⚠️ **본문 텍스트 색은 반드시 변수로.** 하드코딩한 slate hex는 다크모드에서 안 보인다.
새 배경 요소를 만들면 `html.gdark` 오버라이드를 함께 추가한다.

### 색을 써도 되는 유일한 경우

**시장 방향**뿐이다.

- 주가 상승 / 하락 (한국식: 상승 빨강 `--krup`, 하락 파랑 `--krdn`)
- 실제 수익률
- BUY / SELL 의미

그마저도 **숫자와 기호에만** 쓴다. 카드 배경 전체를 칠하지 않는다.

### 하면 안 되는 것

- 분석가마다 다른 색 (QUANT 주황 · FLOW 초록 · DIANA 보라 · TARO 하늘)
  → **이름과 역할 텍스트로 구분한다**
- 컬러 원형 점(dot) → 제거하거나 neutral
- 컬러 progress bar → 제거하거나 neutral
- HOLD 주황 pill 남발
- gradient / neon / glass / glow
- bright blue 남용

### 좋은 예

```
1  QUANT
   확률·통계 분석                      56.7%

2  FLOW
   수급 분석                           56.6%
```

순위는 숫자로, 이름은 굵기로, 값은 tabular numbers와 여백으로 구분한다. 색이 필요 없다.

---

## 2. 계층

계층은 **색상이 아니라** 아래 여섯 가지로 만든다.

Typography · Size · Weight · Spacing · Alignment · Divider

숫자를 강조할 때도 색보다 **font size · weight · tabular numbers · whitespace**를 먼저 쓴다.

---

## 3. 배지 · 아이콘 · Emoji

- `LIVE` `MVP` `발언권` `BEST` `NEW` 같은 것을 전부 배지로 만들지 않는다.
  가능하면 평범한 secondary text로 쓴다.
- 섹션 제목마다 🎯 🔎 🧪 🧭 💉 같은 장식 emoji를 붙이지 않는다.
  의미를 담은 아이콘만 최소한으로 쓴다.
- 이미 자리 잡은 기능 아이콘(📡 레이더, 🧠 정밀분석, 🤖 자동분석)은 **식별자 역할**을 하므로
  유지한다. 새로 만들 때만 자제한다.

---

## 4. 카드

- 정보 하나마다 카드 하나를 만들지 않는다.
- 큰 Section 안에서 **divider · row · column · spacing**으로 나눈다.
- **카드 안 카드**를 최소화한다.
- Border: neutral 1px
- Shadow: 매우 약하게 (`--shadow-sm` 이하)
- Gradient / Neon / Glass: 금지

## 5. 타이포그래피

### 표준 폰트 (2026-08-18 갱신 — 사이트 전체 통일)

모든 공개 화면(index · about · 404 · snap 스냅샷 787개 · 정밀분석 페이지 31개)은
같은 스택을 쓴다:

```
"Wanted Sans Variable","Pretendard Variable",Pretendard,-apple-system,BlinkMacSystemFont,
system-ui,"Apple SD Gothic Neo","Segoe UI","Noto Sans KR","Malgun Gothic",sans-serif
```

- 1순위 **Wanted Sans Variable** — 원터(Wanted) 공식 저장소 배포본, SIL OFL 1.1.
  `assets/fonts/wanted-sans/`에 **self-host**(공식 woff2 서브셋 92개 + `OFL.txt`).
  불러오기는 `<link rel="stylesheet" href="/assets/fonts/wanted-sans/WantedSansVariable.css">`
  한 줄. `unicode-range` 서브셋이라 브라우저는 실제로 쓰는 조각(약 13개)만 내려받고,
  `font-display:swap`이 들어 있어 글자가 안 보이는 구간이 없다.
- 예비(fallback)로 **Pretendard**를 남겨 둔다. 웹폰트를 못 받아도 인상이 유지되고,
  실측 결과 두 글꼴 사이 레이아웃 이동(CLS)은 **0px**이었다.
- ⚠️ 비공식 미러·출처 불명 폰트 파일을 쓰지 않는다. 공식 배포본만.
- ⚠️ Apple SF Pro 폰트 파일을 저장소에 복사·배포하지 않는다(라이선스).
- 새 화면·새 템플릿도 이 스택을 그대로 쓴다. 새 웹폰트를 추가하지 않는다
- 코드·식별자(`code` `kbd` `samp` `pre`)만 고정폭을 쓴다. 브라우저 기본
  `monospace`는 기기마다 글꼴이 달라지므로 `--mono` 스택을 못박아 쓴다
  (기기에 이미 있는 글꼴만 — 새로 내려받는 파일 없음).
- `test_design_contract.py`가 스택·self-host CSS 로딩·jsdelivr 링크 제거·
  **발행된 정적 페이지 재생성 여부**·SF Pro 부재를 검사한다.
  `test_paper_font.js`가 브라우저에서 실제 로드·적용까지 실측한다.

### 크기·굵기

- 설명문 본문: Desktop 약 13~15px · Mobile 약 12.5~14px
- ⭐ **모바일 문장 하한은 12.5px다 (2026-09-06 소유자 지적으로 강제).** 성적표 실측에서
  화면 글자의 **70.5%가 12.5px 미만**이었다("너무 작다"). 문장·숫자는 12.5px 이상,
  표 머리·단위·배지·코드처럼 **읽는 글이 아니라 이름표**에 가까운 것만 12px까지 허용한다.
  12px 미만은 쓰지 않는다. `small` 태그는 부모의 83%로 줄어들어 12.5px 부모에서 10.4px가
  되므로, 표 안 괄호 주석에는 크기를 따로 못박는다.
  회귀는 `test_typography_quality.js`(잘림·가로 스크롤)와 `test_scorecard_lede_browser.js`
  (12px 미만 0)가 잡는다. 글자를 키우면 좁은 격자 칸이 터지므로 **키운 뒤 반드시
  360px·390px에서 잘림을 다시 잰다** — 실제로 모델 대결 머리글 "5일"이 16px 칸에서
  잘렸다(11px일 때 우연히 맞던 것이 12.5px에서 드러났다).
- **굵기는 3단계뿐이다 (2026-08-18 sweep).** 본문 `400` · 라벨 `500` · 제목·강조 `600`.
  브랜드 로고/히어로만 `800` 예외(전체 3곳). `650` `700` `720` `760` `900` 같은
  값은 쓰지 않는다 — 화면마다 굵기가 미묘하게 달라 "페이지마다 다른 사람이 만든"
  인상을 주던 원인이었다(sweep 전 700 이상 1,088곳 → 후 브랜드 2곳).
- ⚠️ 브라우저 기본 굵기가 새는 것도 막아야 한다. `<b>` `<strong>` `<h1~h6>` `<th>`는
  선언을 안 하면 UA 기본 `bold`(=700)로 그려진다. 각 화면 CSS 맨 앞에
  `b,strong{font-weight:600}h1..h6{font-weight:600}th{font-weight:600}`를 둔다.
- 제목에는 `text-wrap:balance`를 건다. 마지막 줄에 한 단어만 떨어지는
  고아 줄바꿈을 **글자를 줄이지 않고** 없앤다.
- 숫자는 `font-variant-numeric: tabular-nums`
- 날짜·상태처럼 **숫자가 아닌 값**은 큰 지표 자리(20px)에 넣지 않는다.
  좁은 칸에서 날짜가 중간에 잘린다(성적표 `.sc-stat-txt` 참고).

한국어 줄바꿈 주의: 콘텐츠 컨테이너에는 `overflow-wrap:anywhere`가 필요하다
(`word-break:keep-all`과 겹치면 `·`로 이어붙인 나열이 뷰포트를 넘친다 — 2026-08-03 실제 사고).

## 7. 화면별 지침

### 모델 대시보드

5개 모델(기본모델 개선판 · 연구 A · 연구 B · 연구 C · 구형 그림자모델)을
**5개의 화려한 카드**로 만들지 않는다. **하나의 Comparison Panel**에 행으로 배치한다.
상태도 Color badge보다 Text hierarchy 중심으로 표현한다.

### 성적표

상단의 채점완료 · 적중 · 빗나감 · 보류 · 종목 · 적중률을 여러 카드가 아니라
**하나의 Summary Grid**로 구성한다. 적중/빗나감 색도 숫자 정도만 semantic color.

**「핵심 3줄 + 펼쳐보기」 (2026-09-06 적용).** 그 위에 결론 3줄을 먼저 둔다.
① 이번 주 채점 결과 ② 시장 흐름을 걷어낸 성적 ③ 그 숫자를 얼마나 믿어도 되는지.
나머지 블록 11개는 세 묶음(이번 주 / 누적 / 연구)으로 접는다. 기본은 '이번 주'만 펼침.

- **숫자를 지우는 게 아니라 접는 것이다.** 펼치면 원래 표가 전부 그대로 나온다.
  실측(390px): 첫 화면 11,986px → 2,857px, 펼치면 13,314px.
- 세 번째 줄의 신뢰 구간은 **판단일 블록 부트스트랩**이다. 채점 건수로 세면 안 된다 —
  같은 날 600종목이 한꺼번에 채점되므로 건수 기준 구간은 실제보다 훨씬 좁게 나와
  실력이 확실한 것처럼 보인다(Constitution `statisticalPolicy.independenceUnit = decision_date`).
- 난수 씨앗을 자료에서 뽑아 **같은 자료면 항상 같은 구간**이 나오게 한다. 다시 그릴 때마다
  숫자가 흔들리면 읽는 사람은 그것부터 의심한다.
- 접힘 상태는 재렌더에도 유지한다(`SC_GROUP_OPEN`). `details`의 `toggle`은 버블링하지
  않으므로 capture 단계에서 받는다.

### 종목 화면 Hero (2026-09-06)

순서는 **무슨 종목인가 → 무슨 판단인가 → 그 판단이 그동안 얼마나 맞았나**다.

1. 종목명(코드) · 현재가 · 기준일 — 15px `600`, 본문색
2. 큰 판단 글자(BUY/HOLD/SELL) — **28~32px**. 예전 34~48px은 종목명을 눌러버렸다
3. 한 줄 설명
4. **그 판단 종류의 실측 성적 한 줄 + 성적표 링크**

4번은 홈 브리핑과 **같은 함수**(`gaeoCallNoteHTML`)를 쓴다. 함수가 둘이 되면 두 화면이
서로 다른 성적을 말하고, 어느 쪽이 맞는지 아무도 모른다. `test_stock_hero.js`가 잠근다.

### BUY 목록의 이름 (2026-09-06)

홈 BUY 목록은 **「매수 우위(BUY) 판단 · 확신도순 · 추천이 아니라 참고예요」**다.
"상위 종목"은 추천처럼 읽힌다. 소유자 지정 기능(확신도순 정렬 · 전체 보기)은
이름만 바꾸고 **지우거나 숨기지 않는다**.

### 가이드북

화려한 색깔 카드 12개로 만들지 않는다. 하나의 Guidebook 안에서
`01` `02` `03` 번호 + 제목 + 짧은 설명 + (필요하면) accordion.
화이트/뉴트럴, 색상 최소. → 2026-08-15 적용 완료.

### Research Hub (snap/index.html)

`generate_snapshots.js`가 자동 생성하는 정적 리서치 허브. 손으로 고치지 말 것(Generator-first).

- Research(뉴스분석·종목공부·주식공부·부동산공부)와 Utility(계산기)를 숫자·화면 모두 분리
- 자동 종목페이지(snap/stock) 절대 미포함 · 정밀분석은 기존 Library 링크 재사용
- Featured는 인기·AI 판단이 아니라 결정적 규칙(발행일 최신 → news→study→lesson→estate → id 큰 글)
- 카드 남발 금지 — Section heading + row + divider + 여백으로만 계층
- 하단 전체 기록(전 글 날짜순 href)은 항상 유지

### 종료된 실험 표시 (2026-08-16)

- 폐기·종료된 실험(예: 종합판단 v3 = 내부 calibrated-ensemble-v3)은 **절대
  '평가 중'처럼 보이면 안 된다.** 사용자용 상태는 「검증 종료 · 서비스 반영 없음」
- Active 성적 영역과 분리해 「과거 실험 기록」 접힌 보조 섹션(작게·중립 회색)으로 내린다
- 실패 기록을 숨기지 않는다 — 최종 표본·성적·통과하지 못한 기준을 그대로 보존
- 큰 컬러 카드·빨간 경고 박스·FAILED 배지 금지. 실패도 차분한 기록으로
- `test_design_contract.py`가 이 계약을 검사한다

### 사용자용 이름 (2026-08-16)

- 내부 버전 ID(`rotation-shadow-v2` · `calibrated-ensemble-v3` · `research_v1.0` 등)를
  **메인 제목이나 큰 수치 자리에 쓰지 않는다.** 각주·기술 상세로만
- 순환매 그림자 검증의 사용자용 이름은 「순환매 검증 기록」
- 자동승격이 없는데 "통과하면 자동으로 바뀝니다"라고 쓰지 않는다 —
  「기준을 채우면 검토 가능 상태가 되고, 실제 적용은 사람이 승인」이 정확한 표현

### 종합 판단 (종목분석 → 종합 판단 탭) — 2026-08-26

이 한 화면에 색이 다섯 가지(초록 「긍정 요인」·주황 「주의 요인」·초록 점·주황 점·
연파랑 번호 원)와 장식 emoji가 다섯 개(🧾 ✅ ⚠️ 🔎 🧭) 몰려 있어서
"한 화면을 여러 사람이 나눠 만든 것"처럼 보였다. 아래를 고정 규칙으로 둔다.

- **구역 하나 = 구분선 하나 + 같은 규격의 제목(`.vsec-title` 13px/600/`--ink`) + 같은 여백.**
  구역마다 카드·테두리·배경을 새로 만들지 않는다. 네 구역(판단 이유 · 긍정·주의 요인 ·
  주요 가격 구간 · 상세 분석 근거)이 모두 같은 리듬을 쓴다.
- **핵심 지표 4개는 카드 4장이 아니라 테두리 하나짜리 패널의 칸(cell)이다**
  (성적표 Summary Grid와 같은 형태 — PC 1×4, 모바일 2×2, 칸 사이는 1px 구분선).
- **긍정/주의는 색으로 구분하지 않는다.** 「긍정」·「주의」라는 말이 이미 뜻을 다 전한다.
  글머리 점은 중립(`--line2`), 소제목은 라벨 단계(11.5px/600/`--dim`).
- **판단색(BUY/HOLD/SELL)은 Hero의 판단 글자 한 곳에만 둔다.** 종합점수 숫자까지 같이
  칠하면 같은 표 안 네 숫자의 색이 제각각이 된다.
- **색을 유지하는 곳**은 실제 시장 방향뿐이다 — 기준가 대비 수익률, 가격 구간의 위/아래 %.
- ⚠️ 구조상 주의: `#vreasons`·`#vfactors`·`#vlevels`·`#vevidence`는 **바깥 컨테이너에만**
  구분선을 건다. 렌더 함수가 안쪽에 같은 class를 한 번 더 만들면 구분선이 두 줄로 겹친다.
- ⚠️ 이 화면의 열 배치는 `display:grid/flex`가 아니라 **`%`폭 + `inline-block`**을 쓴다
  (탭 hidden→표시와 동시에 내용이 채워질 때 자식 stretch가 깨지는 버그 회피 — 2026-08-07).

### about.html

의도적인 Dark Brand page라면 무조건 White로 뒤집을 필요는 없다. 다만
파란색 남발 · 컬러 카드 · 과한 accent · 카드 안 카드 · glow · gradient ·
AI dashboard 느낌은 제거한다. Dark라면 black · charcoal · neutral gray ·
white typography 중심으로, accent는 매우 제한적으로.

## 부록 — 등락 색 계약 (2026-08-31 추가, 자동 검사됨)

### 규칙 한 줄

> **부호가 있는 숫자(등락률·손익·수익률)의 색은 언제나 한국식이다 — 오르면 빨강(`--krup`), 내리면 파랑(`--krdn`).**

### 왜 부록으로 따로 적나

이 규칙은 위 「1. 색」에도 이미 적혀 있었는데, 같은 버그가 **세 번** 반복됐다.

| 시점 | 무엇이 미국식이었나 |
|---|---|
| 2026-08-14 (`44e5141`) | 본문 등락 수치 |
| 2026-08-28 (`qchart`) | 종목 차트 요약 (상승=초록 · 기본값=빨강) |
| 2026-08-30 (`73ea140`, BUG-1) | 종목 화면 추세색 |

세 번 다 사람이 눈으로 찾아 고쳤다. 2026-08-31 전수 조사에서 **여전히 21곳**이
남아 있었고, 그중 최악은 홈 화면이었다.

- `--market-up: #2563EB`(파랑) · `--market-down: #DC2626`(빨강) — **한국식과 정반대**
- 그래서 "오늘 시장 **상승**" 배지가 파란색으로, "오늘 평균 등락 **−1.3%**"가 빨간색으로 나왔다
- 홈에서 "파랑=하락"을 배운 초보자가 손실을 이익으로 오독하는 방향의 사고였다

그래서 이제는 **문서로 부탁하는 대신 테스트로 막는다.**

### 지켜야 할 것

1. **`--market-up`/`--market-down`에 hex를 직접 넣지 않는다.** `var(--krup)`/`var(--krdn)` 별칭만 쓴다.
   값은 `--krup`/`--krdn` 한 곳에서만 고친다.
2. **부호로 색을 고르는 자바스크립트**(`x>0?…:x<0?…`)는 `var(--krup)`/`var(--krdn)`을 쓴다.
   `var(--green)`/`var(--red)`나 `#2F8B73`/`#D5535D` 하드코딩은 금지 — 하드코딩하면 다크모드 대비가 따라오지 않는다.
3. **글자색과 배경 틴트는 같은 방향이어야 한다.** 빨간 글씨에 파란 배경 같은 조합을 남기지 않는다.
4. **방향(`.up`/`.dn`)과 품질(`.ok`/`.bad`)에 같은 클래스를 쓰지 않는다.**
   예전에는 홈 KPI가 둘 다 `.ok`/`.bad`를 써서, 등락 색을 바로잡는 순간 "적중률 65%"까지
   빨갛게(=나쁨처럼) 변하는 부작용이 생겼다.

### 색을 써도 되지만 이 계약의 대상이 아닌 것

방향이 아니라 **의미**를 나타내는 자리다. 여기까지 한국식으로 바꾸면 오히려 뜻이 흐려진다.

- BUY / SELL 판단 배지 · 팀 판단 우세 · 판단 분포 막대
- 적중 / 빗나감 · 적중률 (좋음 초록 · 나쁨 빨강)
- RSI · MACD 같은 지표 구간색
- 경고 · 삭제 · 익절/손절 라벨
- 이동평균선 위/아래(`.ma-badge.above/.below`) — 위치 상태이지 등락이 아니다
- 달력의 `.cal-cell.bull/.bear` — 그날 팀이 BUY를 많이 냈나 SELL을 많이 냈나(판단)이지 주가 등락이 아니다

### 의도된 예외 — 작은 가격 꺾은선(스파크라인) 하나뿐

`priceSparkSVG`가 그리는 종목 칩·시세 카드의 작은 꺾은선만 **세계 공통 방식**
(오르면 초록 `#2F8B73` · 내리면 빨강 `#D5535D`)을 쓴다.

이건 실수가 아니라 결정이다. 화면 안내(「용어 설명」의 꺾은선 범례와 그 아래
「헷갈리기 쉬운 점!」)에서 사용자에게 이렇게 명시하고 있다.

> (참고: 한국 증시는 오르면 빨강·내리면 파랑이지만, 이 **작은 꺾은선만은** 세계 공통 방식대로
> 오르면 초록·내리면 빨강으로 그려요.)

**색과 안내문은 반드시 같이 움직인다.** 색을 바꾸려면 안내문도 함께 고쳐야 하고,
안내문을 지우려면 색도 함께 한국식으로 바꿔야 한다. 테스트가 둘 다 확인한다.
