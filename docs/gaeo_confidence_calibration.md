# GAEO 신뢰도(Confidence) 구조 감사와 Calibration

작성일 2026-08-15 · PHASE A 감사 + 진행 중인 그림자 검증

---

## 1. 현재 신뢰도가 실제로 무엇인가 (코드 추적 완료)

`analyze_auto.py` `chief_eval()`:

```
scores = [TARO, DIANA, QUANT, FLOW]
spread = max(scores) - min(scores)
conf   = clamp( max(40, 88 - spread) - risk.confidencePenalty, 30, 90 )
```

`risk.confidencePenalty`는 위험등급에 따라 0 / 3 / 10.

**결론: 현재 신뢰도는 확률이 아니다.**
분석가 4인의 점수가 서로 얼마나 가까운지(의견 일치도)를 잰 값이다.

실측 검증:

- spread와 conf의 상관계수 **r = -0.93** (사실상 spread의 일차변환)
- conf와 실제 적중 여부의 상관계수: BUY 판단 기준 **r = 0.10** (매우 약함)

즉 **"의견이 일치한다"와 "실제로 맞는다"는 거의 별개다.**

## 2. 신뢰도 표의 착시

전체 신뢰도 구간별 성적(BUY+SELL 합산, 전체 누적):

| 구간 | 건수 | 적중률 | 시장 대비 |
|---|---|---|---|
| 전체 | 6,607 | 52.5% | 50.5% |
| 55% 이상 | 2,516 | 58.3% | 52.4% |
| 65% 이상 | 1,048 | 65.3% | 56.4% |
| 70% 이상 | 634 | 67.9% | 56.4% |

겉보기엔 신뢰도가 잘 작동하는 것처럼 보인다(52.5% → 67.9%).

**그러나 BUY와 SELL을 분리하면 그림이 뒤집힌다:**

| 구간 | BUY 건수 | BUY 적중률 | SELL 건수 | SELL 적중률 |
|---|---|---|---|---|
| 전체 | 808 | 43.3% | 5,799 | 53.7% |
| 55% 이상 | 358 | 48.5% | 2,158 | 59.8% |
| 60% 이상 | 182 | 49.0% | 1,388 | 62.5% |
| 65% 이상 | **44** | **37.1%** | 1,004 | 66.3% |
| 70% 이상 | **7** | **28.6%** | 627 | 68.4% |

- 표본의 **88%가 SELL**이다. 합산 표의 개선은 사실상 SELL이 끌어올린 것이다.
- **BUY만 보면 신뢰도가 높아져도 성적이 좋아지지 않는다.**
  최상위 구간은 오히려 떨어진다(표본이 44건, 7건으로 매우 작아 노이즈 가능성 큼).

이 착시를 없애기 위해 2026-08-14에 성적표의 신뢰도 표를 BUY/SELL 분리 표시로 변경했다.

## 3. 대안 후보와 그림자 검증 (구현 완료, 미승격)

`compute_model_intelligence.py`에 다음을 추가했다.

- `confidence_calibration_from()`:
  학습 구간에서만 (판단 종류 BUY/SELL, 종합점수 5점 구간) → **실측 적중률** 표를 만든다.
  PAVA로 단조성을 강제해 표본 노이즈로 인한 역전을 누른다.
- `evaluate_confidence_model()`:
  **학습에 전혀 쓰지 않은 검증 구간**에서 기존 신뢰도와 후보 신뢰도 중
  어느 쪽이 적중 여부를 더 잘 가르는지 비교한다
  (상위 1/3과 하위 1/3의 적중률 차이, 상관계수).

분할 방식: 날짜 기준 70/30 + **5일 embargo**(예측 지평이 검증 구간에 겹치지 않도록 경계 앞 5일 제거).

승격 조건(모두 만족해야 화면 반영):

- 검증일 40거래일 이상
- 검증 BUY 50건 이상, SELL 50건 이상
- 후보의 상위/하위 1/3 적중률 차이가 5%p 이상이면서 기존보다 클 것

### 첫 실행 결과 (정직하게 기록)

| 지표 | 기존 신뢰도 | 후보 신뢰도 |
|---|---|---|
| 상위 1/3 - 하위 1/3 적중률 차 | -1.7%p | **-17.3%p** |
| 상관계수 | -0.032 | -0.479 |
| 검증 거래일 | 6일 (40일 필요) | 동일 |

**미승격.** 이유 두 가지:

1. 검증 구간이 6거래일뿐이라 애초에 판정 자격 미달
2. 그 짧은 구간(급등장)에서는 후보가 기존보다 **더 나빴다**

후보 값이 음수라는 것은 "신뢰도가 높다고 한 판단이 오히려 더 틀렸다"는 뜻이다.
따라서 승격하지 않았고, 반등 가드/순환매/종합판단 v3와 같은 원칙으로
그림자 상태로만 계속 검증한다. 이 결과는 성적표 화면에 그대로 공개돼 있다.

## 4. 스펙 44번 요구: 신뢰도를 둘로 분리 (미구현, PHASE B)

목표 구조:

- **A. FORECAST PROBABILITY**: 예) 5거래일 목표 달성확률 64%
- **B. DATA / MODEL RELIABILITY**: 예) B등급

현재는 이 둘이 한 숫자에 섞여 있다(의견 일치도 + RISK 감점).
분리해야 한다. 확률과 신뢰등급을 하나의 숫자로 합치지 않는다.

## 5. 스펙 45번 요구: Calibration 지표 (미구현, PHASE E)

아직 구현되지 않은 필수 항목:

- Brier Score (BUY/HOLD/SELL 각각, 5D/20D/60D 각각)
- Log Loss
- Per-class Reliability Curve
- Calibration Slope / Intercept
- Block Bootstrap Confidence Interval

현재 `model_intelligence.js`에 Brier가 있으나 v3 후보 모델 전용이며,
클래스별/지평별로 분리돼 있지 않다.

ECE는 보조지표로만 쓰고 단독 판단 근거로 삼지 않는다.

## 6. 현재 답변

**"기존 Confidence를 실제 Probability라고 부를 수 있는가" → NO.**

의견 일치도 지표이지 확률이 아니다.
화면에서 "%"로 표시되지만 실제 발생빈도와 연결되어 있지 않다.
BUY 판단에서는 예측력이 거의 없다(r = 0.10).
