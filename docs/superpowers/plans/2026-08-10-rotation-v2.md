# GAEO Rotation v2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기존 순환매 점수와 자동화를 보존하면서 점수의 의미·기여도·변화·기간별 실제 성과·TARO 관심 종목을 투명하게 설명하는 Rotation v2.0을 완성한다.

**Architecture:** `rotation_engine.py`가 현재 시점의 설명 가능한 Score와 종목 후보를 만들고, `backtest_rotation.py`가 날짜순 1·3·5·20일 성과와 추천기간을 `rotation_model.json`에 저장한다. `compute_rotation.py`는 일별 아카이브와 모델을 결합해 v2 선택 필드를 추가하며, `rotation-ui.js`는 기존 필드만 있는 v1 스냅샷에도 계속 동작한다.

**Tech Stack:** Python 3.11 표준 라이브러리, unittest, Vanilla JavaScript, 정적 HTML/CSS, 결정론적 SVG, GitHub Actions

## Global Constraints

- 기존 Score와 필드는 삭제하거나 의미를 바꾸지 않는다.
- 실제 데이터가 없는 통계·점수 변화·거래대금·확률을 만들어내지 않는다.
- 1·3·5·20일은 검증 대상 관찰기간, 60·120·200일은 추세 문맥으로 구분한다.
- 모든 as-of 계산은 평가일 이후 행을 보지 않는다.
- LLM API, 네트워크 호출, 외부 DB를 추가하지 않는다.
- 자료 부족은 `null`과 `자료 축적 중`으로 표현한다.
- Emoji, 캐릭터, Neon, Glow, Gaming/Crypto UI를 사용하지 않는다.
- 사용자 노출 문구에 em dash를 사용하지 않는다.
