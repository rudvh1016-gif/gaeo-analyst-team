# GAEO 순환매 분석 시스템 설계

- 작성일: 2026-08-10
- 상태: 사용자 승인 완료
- 대상 저장소: GAEO Analyst Team 정적 사이트
- 구현 원칙: 실제 데이터, 규칙 기반 계산, LLM 토큰 0, 미래 데이터 누출 금지

## 1. 제품 목표

순환매 페이지는 500개 추적 종목의 가격, 상대강도, 거래 흐름, 업종 확산도, 기술적 상태와 과거 패턴을 분석해 다음 내용을 이해하기 쉽게 보여준다.

1. 지금 어떤 업종에 힘이 모이고 있는가
2. 상승이 업종 전체로 퍼지는가, 일부 대장주에 집중되는가
3. 다음 순환 후보로 관찰할 업종이 있는가
4. 비슷한 과거 시장에서 이후 흐름이 어땠는가
5. 현재 결론을 얼마나 신뢰할 수 있는가

이 기능은 다음 업종의 상승을 확정하는 예측기가 아니다. 근거가 약하면 반드시 `뚜렷한 순환 신호 없음` 또는 `관찰`을 반환한다.

## 2. 범위와 비범위

### 포함

- 상단 및 모바일 전체 메뉴의 `순환매` 진입점
- `?m=rotation` 독립 화면
- 24개 현행 업종의 자동 집계
- 1, 3, 5, 20일 신호와 60, 120, 200일 장기 구조
- 업종 크기와 작은 표본 보정
- 대장주 집중도
- KOSPI, KOSDAQ, 500종목 유니버스 대비 상대강도
- 거래 흐름, 확산도, TARO 확인
- 시장 국면, Lead-Lag, 과거 유사 시장
- 신뢰도 보정과 무신호 차단
- 정적 스냅샷, 자동 실행, Walk-forward 백테스트
- PC, 모바일, 다크모드, 키보드, 모션 감소 환경

### 초기 구현에서 제외

- AI가 생성하는 매수, 매도 추천
- 브라우저에서 500종목 원천 데이터를 매번 재계산하는 방식
- 외부 DB 또는 상시 실행 서버
- 뉴스 감성 점수를 순환매 핵심 점수에 직접 반영하는 방식
- 현재 데이터로 검증되지 않은 5년 통계 문구
- 과거 시가총액 이력 없이 수행하는 시가총액 가중 백테스트

## 4. 검토한 구현 방식

### 방식 1. 모든 계산을 30분마다 실행

구조는 단순하지만 Lead-Lag, 유사 시장과 백테스트가 기존 분석 갱신 시간을 늘린다. 기존 자동화 체인이 느려지거나 실패할 위험이 높아 채택하지 않는다.

### 방식 2. 장중과 정기 계산 분리

장중에는 최신 가격으로 가벼운 순환 상태를 계산한다. 장 마감에는 최종 스냅샷, 주간에는 Lead-Lag, 월간에는 백테스트와 신뢰도 교정을 수행한다. 기존 정적 구조를 유지하면서 안정성과 통계 품질을 지킬 수 있어 채택한다.

### 방식 3. 외부 DB와 분석 서버

대규모 이력에는 유리하지만 비용, 로그인, 운영 복잡도가 증가한다. 현재 요구 범위에는 과하므로 채택하지 않는다.

## 7. 업종 Aggregation

각 업종과 기간 `h`에 다음 값을 계산한다.

- 동일가중 평균 수익률
- 중앙값 수익률
- 상하위 극단값을 제한한 Winsorized 평균
- 상승, 하락, 보합 종목 비율
- 수익률 분산과 중앙절대편차
- MA5, 20, 60, 120, 200 위 종목 비율
- MACD 개선 종목 비율
- 거래 흐름 증가 종목 비율
- 52주 고가, 저가 접근 종목 비율
- Top1, Top3, Top5 집중도

기본 업종 수익률은 중앙값, Winsorized 평균, 동일가중 평균을 투명한 동일 비중 기준으로 시작한다. 최종 공개 가중치는 Walk-forward 결과로만 조정하며 음수 가중치나 한 지표 독점은 허용하지 않는다.

현재 시가총액은 설명용 집중도에 사용할 수 있지만 과거 시가총액이 없으므로 백테스트 수익률에는 사용하지 않는다.

## 8. 작은 표본 보정

### 비율 지표

상승 종목 비율처럼 성공과 실패로 표현되는 값은 Beta-Binomial 방식으로 보정한다.

```text
보정 비율 = (업종 성공 수 + prior_strength × 시장 성공 비율)
            / (업종 유효 종목 수 + prior_strength)
```

`prior_strength`는 초기 임의 상수가 아니라 과거 업종 간 분산을 이용한 Empirical Bayes로 추정한다. 추정에 필요한 이력이 부족하면 보수적인 공통값을 사용하고 신뢰도를 낮춘다.

### 연속 지표

업종 수익률과 상대강도는 다음과 같이 전체 업종 중앙값 방향으로 축소한다.

```text
보정값 = reliability × 관찰값 + (1 - reliability) × 전체 업종 중앙값
reliability = 유효 종목 수 / (유효 종목 수 + shrinkage_strength)
```

화면에는 `표본 신뢰도 보통 · 6종목`처럼 유효 종목 수를 함께 표시한다.

## 9. 상대강도와 Benchmark

각 종목을 현재 시장 소속에 맞는 지수와 비교한 후 업종으로 집계한다.

- KOSPI 종목: 종목 수익률 - KOSPI 수익률
- KOSDAQ 종목: 종목 수익률 - KOSDAQ 수익률
- 업종: 종목별 초과수익률의 중앙값 및 Winsorized 평균
- 보조 기준: 500종목 유니버스 중앙값 대비

기간은 1, 3, 5, 20, 60, 120, 200일이다. 현재 시장 소속 정보만 보유하므로 과거 시장 이전이 있었던 종목은 백테스트 신뢰도에서 감점한다.

## 10. 거래 흐름

완성 제품에서 `거래대금`이라고 표시하려면 정확한 일별 거래대금 원천 필드를 추가하고 과거 이력을 백필해야 한다.

그 전까지 사용할 수 있는 값은 다음과 같다.

- 최근 거래량 / 최근 5일 평균 거래량
- 최근 거래량 / 최근 20일 평균 거래량
- 업종 Median Relative Volume
- 거래량 증가 종목 비율
- 종가 × 거래량 추정치

종가 × 거래량은 화면에서 `추정 거래대금` 또는 `거래량 기반 자금 흐름`으로만 표시한다. 정확한 거래대금과 혼용하지 않는다.

## 11. 대장주 집중도

업종의 양의 수익 기여분을 기준으로 Top1, Top3, Top5 비중을 계산한다.

- 동일가중 수익 기여 집중도
- 거래량 기반 기여 집중도
- 현재 시점 보조용 시가총액 기여 집중도

Top3 집중도가 과도하면 `업종 전체 확산` 점수와 최종 신뢰도를 낮춘다. 상승률이 높아도 나머지 종목의 중앙값과 확산도가 약하면 `일부 대장주 중심`으로 설명한다.

## 12. TARO 연결

TARO 정의를 중복 구현하지 않는다. 현재 `compute_indicators.py` 안의 기술지표 계산을 공용 순수 함수 모듈로 추출하고 기존 지표 출력과 순환매 백테스트가 함께 사용한다.

업종 TARO 확인 점수는 다음으로 구성한다.

- MA5, 20, 60, 120, 200 위 종목 비율
- MA20, 60 기울기 개선 비율
- MACD 개선 비율
- RSI 과열과 과매도 분포
- 거래량 확인 비율
- 단기와 중기 추세 동시 개선 종목 수

TARO는 자금 이동 방향을 결정하지 않는다. 순환매 신호가 업종 내부 종목의 실제 기술 상태와 일치하는지 확인한다.

## 13. Market Regime

시장 국면은 한 단어가 아니라 네 축으로 저장한다.

1. 방향: 상승, 하락, 횡보
2. 변동성: 확대, 보통, 축소
3. 시장 주도: KOSPI, KOSDAQ, 중립
4. 확산도: 개선, 중립, 악화

방향은 지수의 MA20, 60, 200 위치와 기울기, 변동성은 20일 실현 변동성의 과거 백분위, 시장 주도는 KOSDAQ과 KOSPI의 20일 상대수익률, 확산도는 500종목의 상승 비율과 MA 위 비율 변화로 판단한다.

과거 데이터가 충분해질 때만 대형주와 중소형주 주도 축을 추가한다. 현재 시가총액 이력만으로 과거 국면을 소급 생성하지 않는다.

## 14. Lead-Lag Network

24개 업종의 일별 시장대비 초과수익률을 사용한다.

- 후보 시차: 1~20거래일
- 기본 계산 창: 최근 120일과 250일
- 최근 구간과 이전 구간에서 방향이 유지되는지 확인
- 여러 업종과 여러 시차를 동시에 비교하므로 다중검정 보정 적용
- 통계적으로 약하거나 두 구간에서 재현되지 않는 관계는 Edge에서 제외
- 주간 재계산, 장중에는 캐시 재사용

현재 291거래일은 250일 창 하나를 겨우 충족한다. 초기 Lead-Lag는 `탐색적 관계`로 표시하고 높은 신뢰도 Edge를 허용하지 않는다. 3년 이상 이력이 확보된 후 정식 신뢰도 기준을 연다.

## 15. Historical Similarity

각 날짜의 시점에서 알 수 있었던 정보만 이용해 Feature를 만든다.

- KOSPI, KOSDAQ 추세와 변동성
- 시장 확산도
- 업종별 상대강도 순위
- 업종별 거래 흐름 순위
- 3, 5, 20일 모멘텀
- 60일 추세
- 이동평균 구조
- 당시 사용 가능했던 Lead-Lag 상태

표준화 평균과 분산은 해당 날짜 이전 데이터로만 계산한다. 현재 시점과 너무 가까운 날짜, 서로 결과 구간이 겹치는 날짜, 평가하려는 미래 20일이 남아 있지 않은 날짜는 후보에서 제외한다.

유사도는 순위 기반 거리와 정규화된 연속 Feature 거리를 결합한다. 최소 유사도 아래의 사례는 포함하지 않는다. 사례 수, 단순 재현률, 유사도 가중 재현률, 평균과 중앙값 초과수익률, 성공과 실패 수를 함께 저장한다.

현재 이력으로 유효 사례가 부족하면 사례 통계를 만들지 않고 `통계 축적 중`으로 표시한다.

## 16. Rotation Score

기간별로 다음 8개 모델을 각각 0~100으로 정규화한다.

1. Momentum
2. Relative Strength
3. Flow or Volume
4. Breadth
5. Lead-Lag
6. Historical Similarity
7. Market Regime Match
8. TARO Confirmation

초기 Shadow 모델은 동일 비중으로 기록만 쌓는다. 공개 가중치는 Walk-forward 결과에서 다음 제약으로 선택한다.

- 모든 가중치는 0 이상
- 합계는 1
- 한 모델 최대 비중 제한
- 동일 비중에서 크게 벗어나면 성능 향상이 명확해야 함
- 1, 3, 5, 20일 Horizon별 별도 가중치

표본 부족, 대장주 집중, 모델 불일치와 데이터 누락은 점수 자체보다 신뢰도 및 Gate에 우선 반영한다.

## 17. Confidence Calibration과 Gate

신호 강도와 신뢰도는 별개다. 높은 점수라도 과거 사례가 부족하면 높은 신뢰도로 표시하지 않는다.

### 신뢰도 입력

- 데이터 커버리지
- 업종 유효 종목 수
- 과거 유사 사례 수
- 모델 방향 일치도
- 시장 국면 안정성
- 거래 흐름 확인 여부
- 대장주 집중도
- 최근 구간 재현성
- Walk-forward 예측 확률 교정 상태

### 출력

- 높음
- 보통
- 낮음
- 관찰
- 뚜렷한 순환 신호 없음

높음은 다음 조건을 모두 충족한 경우에만 허용한다.

- 유효 데이터 커버리지 80% 이상
- 업종 표본 신뢰도 기준 충족
- 충분한 비중의 독립 모델이 같은 방향
- 충분한 과거 평가 사례
- Walk-forward에서 높음 그룹 성능이 보통 그룹보다 실제로 우수
- 거래 흐름과 확산도 중 적어도 하나가 명확하게 확인
- 대장주 집중도 제한 통과

높음 그룹이 보통보다 우수하지 않으면 자동으로 보통 이하로 내린다.

## 22. Rotation Map

- Node 크기: 현재 순환 강도와 신뢰도

## 27. Walk-forward Backtest

각 평가 날짜 `t`에서 다음 순서를 지킨다.

1. `t`까지 공개된 데이터만 로드
2. `t` 이전 데이터만으로 표준화, 가중치, 유사 사례와 국면 정의
3. `t` 시점의 1, 3, 5, 20일 업종 순위 생성
4. 실제 미래 구간이 끝난 뒤 결과 채점
5. 한 거래일 앞으로 이동해 반복

Random split은 사용하지 않는다. 유사 사례 검색에는 결과 구간과 겹치지 않는 Embargo를 둔다.

### 평가 지표

- Top-1 Hit Rate
- Top-3 Hit Rate
- 평균 및 중앙값 초과수익률
- 업종 순위 상관
- Horizon별 Hit Rate
- 시장 국면별 Hit Rate
- 신뢰도 Calibration
- 신호 후 최대 낙폭
- 신호 빈도
- No-Signal Accuracy

현재 업종 분류와 시장 소속을 과거 전체에 적용한 결과에는 `현재 분류 기준` 경고와 신뢰도 감점을 적용한다.

## 28. 장애와 데이터 부족 처리

- 유효 종목 80% 미만: 해당 업종 신뢰도 하향
- 핵심 기간 데이터 부족: 그 기간 점수 `insufficient`
- 정확한 거래대금 없음: 거래량 기반 표시
- Lead-Lag 이력 부족: Edge 숨김 또는 탐색적 표시
- 유사 사례 최소 수 미달: 사례 통계 숨김
- 모델 파일 없음: 동일 비중 Shadow 모델로 관찰만 표시
- 일부 종목 파싱 실패: 전체 계산을 중단하지 않고 유효 수 표시
- 스냅샷 생성 실패: 마지막 정상 파일 유지
- 데이터 기준 시각이 오래됨: 화면 상단에 오래된 데이터 경고
