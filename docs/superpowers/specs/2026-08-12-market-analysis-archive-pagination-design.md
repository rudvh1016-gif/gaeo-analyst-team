# 메인 시장분석 보관함 전환 설계

## 목표

메인 화면의 정보 밀도를 낮추기 위해 현재 시장분석 본문을 PC와 모바일에서 직접 노출하지 않는다. 시장분석은 `지난 시장 분석` 보관함에서만 확인하며 최신순으로 한 페이지에 4건씩 탐색한다.

## 화면 구성

- 현재 기준 브리핑, 코스피·코스닥 지수, 시장 국면, 오늘의 종합 판단은 기존대로 유지한다.
- `LIVE_AN.market`의 긴 현재 시장분석 본문과 포인트 목록은 메인 본문에서 제거한다.
- `지난 시장 분석`은 접힌 한 줄 헤더로 유지해 메인 화면의 세로 길이를 줄인다.
- 보관함을 펼치면 최신순 4건만 표시한다.
- 기록이 5건 이상이면 이전, 페이지 번호, 다음 버튼을 표시한다.
- 페이지를 바꾸면 열려 있던 날짜 상세를 닫고 해당 페이지의 첫 항목으로 탐색 흐름을 유지한다.
- PC와 모바일에서 같은 자료와 페이지 규칙을 사용하며, 모바일 버튼은 줄바꿈을 허용한다.

## 데이터 흐름

- 화면 렌더링 시 자동 생성 파일 `market_history.js`의 `MARKET_HISTORY`를 복사해 사용한다.
- 현재 `LIVE_AN.market`에 본문 또는 포인트가 있으면 `updated`의 날짜를 키로 보관함 데이터에 즉시 합친다.
- 같은 날짜가 이미 있으면 현재 분석으로 교체해 중복을 만들지 않는다.
- 따라서 시장분석을 갱신한 직후에는 별도의 수동 보관 작업 없이 보관함 첫 항목에 보인다.
- 기존 `archive_analysis.py` 누적 로직은 그대로 유지해 다음 자동화 실행 때 `market_history.js`에 영구 보관한다.
- 자동 생성 파일 `market_history.js`는 직접 편집하지 않는다.

## 동작 및 접근성

- 페이지 크기는 `4`로 고정한다.
- 페이지 버튼에는 현재 페이지를 나타내는 `aria-current="page"`를 사용한다.
- 이전·다음 버튼은 첫 페이지와 마지막 페이지에서 비활성화한다.
- 페이지 상태는 메인 화면 세션 안에서만 유지하며 새로고침 시 최신 1페이지로 돌아간다.
- 보관 기록이 없으면 시장분석 영역 전체를 표시하지 않는다.

## 검증 기준

- 현재 시장분석 제목과 본문이 보관함 밖에 렌더링되지 않는다.
- 현재 분석이 같은 날짜의 과거 기록을 중복 없이 최신 내용으로 교체한다.
- 25건이면 첫 페이지에 4건만 렌더링되고 총 7페이지가 표시된다.
- 다음 페이지 이동 시 5~8번째 기록이 표시된다.
- 4건 이하에서는 페이지 이동 UI가 나타나지 않는다.
- 기존 시장분석 누적 스크립트와 다른 메인 화면 계약 테스트가 계속 통과한다.
