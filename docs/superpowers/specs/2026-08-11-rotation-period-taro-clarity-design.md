# 순환매 기간·TARO 표기 명확화 설계

- 작성일: 2026-08-11
- 목적: 순환매 화면에서 현재 흐름의 계산기간, 미래 관찰기간, 과거 검증기간을 분리하고 후보 종목의 실제 TARO 점수와 거래량 비교 기준을 정확히 표시한다.

## 문제와 원인

상단 대표 업종은 `rotation_engine.py`에서 5거래일로 고정되어 있으나 추천 관찰기간은 Walk-forward 결과에 따라 별도로 선택된다. 현재 추천은 20거래일이므로 같은 화면에서 5일 업종 순위와 20일 추적기간이 혼재한다. 시장 국면 카드도 방향·변동성·시장 주도는 20·60일 자료를 쓰면서 상승 종목 비율만 5일 자료를 사용하고, 이를 `상승 폭`이라고 잘못 표현한다.

후보 종목의 `TARO`는 실제 `analyze_auto.py` TARO 점수가 아니라 `rotation_engine.py`가 이동평균·MACD·거래량 조건을 이진 가점으로 다시 계산한 별도 점수다. 이 때문에 실제 TARO 최대값이 95점임에도 화면에 100점이 표시된다. 거래량 배수는 오늘 거래량을 오늘을 제외한 직전 20거래일 평균 거래량으로 나눈 값이지만 화면에 분모와 비교기간이 없다.

## 채택 설계

1. 상단 대표기간과 초기 선택기간을 `recommendedHorizon.horizon`에 연동한다. 추천자료가 없을 때만 5거래일을 사용한다.
2. 상단 카드에 현재 계산기간의 시작일과 종료일을 표시한다. 현재 20거래일은 2026-07-13~2026-08-11이다.
3. 추천기간이 5일이 아닐 때 최근 5거래일 1위 업종을 `단기 참고`로 별도 표시한다.
4. 시장 국면은 `방향·변동성·주도시장: 최근 20거래일`, `상승 종목 비율: 최근 5거래일`로 항목과 기간을 분리한다. `상승 폭` 표현은 제거한다.
5. 추천 관찰기간은 `신호 다음 거래일부터 N거래일`로 정의하고, 검증기간·중첩 평가 표본 수를 표시한다. 표본 수를 거래일 수 또는 독립확률로 오해하지 않도록 명시한다.
6. 후보 종목은 `auto_analysis.js`의 실제 TARO 점수를 사용한다. 동일 날짜 자료가 없을 때는 별도 점수를 TARO로 표시하지 않고 기술조건 점수로 구분한다.
7. 거래량은 `오늘 거래량 / 직전 20거래일 일평균`으로 정의하고, 배수와 실제 비교기간을 후보 데이터에 저장해 화면에 표시한다.
8. 후보 정렬은 실제 TARO 점수, 업종 내 상대강도, 종목명 순으로 유지한다.

## 데이터 흐름

`compute_indicators.py`가 기술지표와 거래량 배수를 생성하고 `analyze_auto.py`가 실제 TARO 점수를 생성한다. 이후 `compute_rotation.py`가 두 자료를 함께 읽어 후보 종목과 기간 메타데이터를 `rotation_snapshot.js`에 저장한다. UI는 스냅샷에 저장된 원천·기간을 그대로 표시하며 자체 추정으로 이름을 붙이지 않는다.

## 검증

- 실제 TARO와 후보 카드 점수가 일치한다.
- 100점으로 잘못 표시되던 종목이 실제 점수로 표시된다.
- 거래량 배수에 직전 20거래일 평균 대비와 비교기간이 표시된다.
- 추천 20일일 때 상단 대표 업종과 초기 탭이 20일 순위를 사용한다.
- 시장 상승 종목 비율과 Walk-forward 표본에 각각 기간과 정의가 표시된다.
- Python 단위 테스트, UI 계약 테스트, 워크플로 테스트 및 브라우저 렌더링 검증을 통과한다.
