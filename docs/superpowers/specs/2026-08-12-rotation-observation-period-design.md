# 순환매 예상 관찰기간 표시 설계

## 목적

`다음 관찰 후보`가 1위로 바뀔 날짜는 현재 계산 구조로 예측하지 않는다. 대신 현재 추천 관찰 기간에 맞춰, 신호 다음 거래일부터 실제로 지켜볼 예상 기간을 날짜로 보여준다.

## 표시 규칙

- 표시 위치: 상단 `다음 관찰 후보` 카드의 점수와 계산기간 아래
- 표시 문구: `예상 관찰기간 YYYY.MM.DD~YYYY.MM.DD (N거래일·휴장일 제외)`
- 시작일: 스냅샷 기준 종가일의 다음 KRX 거래일
- 종료일: 시작일을 첫째 날로 세어 추천된 `N`번째 KRX 거래일
- 2026-08-11 종가와 20거래일 기준 예시: `2026.08.12~2026.09.09`
- 후보가 없거나 추천 기간이 준비되지 않은 경우에는 표시하지 않는다.

## 계산과 데이터 흐름

Python 스냅샷 생성 단계에서 주말과 알려진 KRX 휴장일을 제외해 기간을 산출한다. 결과는 `summary.candidateObservationPeriod`에 `periodStart`, `periodEnd`, `tradingDays`로 저장한다. UI는 계산을 반복하지 않고 이 필드를 날짜 형식으로만 표시한다.

## 안전 장치

- 1위 전환 예상일, 추천 예상일, 확률이라는 표현을 사용하지 않는다.
- 기존 후보 선정 점수와 순위 계산은 변경하지 않는다.
- KRX가 공지한 공휴일·근로자의 날·연말 휴장 규칙을 반영한다.
- 원격 휴일 API에 의존하지 않아 정적 사이트 생성이 실패하지 않게 한다.

## 검증

- 2026-08-11 다음 20거래일이 2026-08-12~2026-09-09인지 단위 테스트한다.
- 후보가 있을 때 스냅샷 필드가 생성되고 없을 때 생략되는지 확인한다.
- 렌더링 결과에 예상 관찰기간 문구가 정확히 나타나고 1위 전환 예상일 문구는 없는지 확인한다.
- 기존 Python·JavaScript 회귀 테스트와 모바일 렌더링 계약을 모두 실행한다.
