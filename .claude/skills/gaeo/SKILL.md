# GAEO TEAM: 무엇을 쓸지 고르는 안내판

이 스킬은 **안내만 한다.** 어떤 파일도 고치지 않고, 다른 스킬을 대신 실행하지도 않는다.
대표가 목록을 보고 직접 고르면 그때 해당 스킬이 실행된다.

## 할 일

아래 표를 **그대로 출력**하고, 마지막에 "어떤 걸 할지 골라 주시면 바로 시작하겠습니다"라고 안내한다.
대표가 이미 하고 싶은 일을 말했다면 표를 띄운 뒤 어느 스킬이 맞는지 한 줄로 추천한다.

## GAEO TEAM 8개 스킬

| 이럴 때 | 쓰는 것 | 파일을 고치나 |
|---|---|---|
| 다음에 뭘 만들지 모르겠다 | `/gaeo-strategy` | 아니오 (제안만) |
| 화면이 안 예쁘다 · 모바일이 불편하다 | `/gaeo-design` | 아니오 (제안만) |
| 만들기로 정한 걸 실제로 만든다 | `/gaeo-build` | 예 |
| 방금 만든 걸 배포 전에 검사한다 | `/gaeo-review` | 아니오 (검사만) |
| 뭔가 고장났다 · 오류가 난다 | `/gaeo-bug` | 예 |
| 분석이 진짜 맞는지 확인한다 | `/gaeo-quant` | 경우에 따라 |
| 사람이 더 들어오게 하고 싶다 | `/gaeo-growth` | 경우에 따라 |
| 사이트 전체를 한 번 훑는다 | `/gaeo-health` | 아니오 (진단만) |

## 헷갈리기 쉬운 경계

- **Strategy vs Health**: Strategy는 "앞으로 뭘 할까"(미래), Health는 "지금 어디가 아픈가"(현재).
- **Design vs Build**: Design은 개선안 제안까지, Build는 구현부터.
- **Bug vs Review**: Bug는 이미 난 문제를 고치는 것, Review는 배포 전에 문제를 찾는 것.

## 보통의 흐름

```
/gaeo-strategy (뭘 할지 정한다)
      ↓
/gaeo-build (만든다)
      ↓
/gaeo-review (검사한다)
      ↓  PASS면
커밋 · 배포
```

Review에서 FAIL이 나오면 배포하지 않고 `/gaeo-bug` 또는 `/gaeo-build`로 돌아간다.
